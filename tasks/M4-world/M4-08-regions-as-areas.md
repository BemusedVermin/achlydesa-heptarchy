# M4-08 · Regions drawn by hand as areas

## Goal

A region is a named area of the one world, drawn by hand in content, that carries data (tags, props such as decay, and lists). Formulas and the region panel read the region a cell lies in.

## Context

- `docs/go-technical-design.md` → "Level of detail" (Regions are areas of one world; drawn by hand for now, generated by procgen later).
- `docs/game-design.md` → "The living deep" (Outcomes emerge), "Candidates and seats" (the piece reports a seat's region; M7 uses this).
- The brief's "Decisions" (regions) and "The one-world model" → "Regions".
- What exists after M4-07: `region` in `NeedEnv`, `BehaviorEnv` and `RankEnv` is the empty record; `api.RegionView` has only a name; `agents.regionRecord`; `content.Record`; `remnant` content reads `region.props.decay`.

## Deliverables

- `internal/content/types.go`: `RegionDef` (below) and `Bundle.Regions`; the `region.` prefix; regenerate the schemas.
- `internal/content/regions.go`: checks (boxes inside the world's bounds; a name text) and `Registry.RegionAt(cell) (api.ContentID, bool)`, built once at load as a lookup the size of the world's chunks, not a per-cell table.
- `internal/core/agents`: `region` in need, behavior and rank formulas is the record of the region the body's cell lies in, or the empty record. The region view names the region the party's leader stands in.
- `content/data/regions.cue`: one region per existing place, as a box around it, carrying the props the maps' regions carried (decay). Tags such as `crawlspace` and `town` move here.
- `internal/frontend/tui`: the region panel draws the region's name; update `region_town.golden`.
- Tests: a cell in two overlapping boxes gets the smaller one; a cell in none gets no region; a remnant's undecayed need rises in a high-decay region and not in a low one.
- `docs/content-guide.md`: a "Regions" section with a recipe. `docs/glossary.md`: **region** is "a named area of the one world, drawn in content, carrying data formulas read; it holds no population".

## Spec

Suggested shape:

```go
// RegionDef is a named area of the world, drawn as boxes.
type RegionDef struct {
	Data
	Name  api.ContentID
	Boxes []RegionBox
}

// RegionBox is the cells from column FromCol to ToCol, row FromRow to ToRow and depth FromDepth to ToDepth, inclusive.
type RegionBox struct {
	FromCol, ToCol, FromRow, ToRow, FromDepth, ToDepth int
}
```

- **Overlap.** Where boxes of different regions overlap, the region whose box there has the fewest cells wins; on a tie, the lower region ID. Firm: it lets a town sit inside a larger region of the deep.
- Provisional: boxes are the whole drawing tool for now. Procgen (M5) will emit the same records.
- A region holds no population, stock or residents (rule 10). A crawlspace is a region tagged `crawlspace`.
