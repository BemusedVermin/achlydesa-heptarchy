# M1-06 · content: CUE loader, IDs, text, formulas

## Goal

Content is CUE data checked against schemas generated from Go structs, loaded into one immutable registry, with stable namespaced IDs, player-facing text and compiled Expr formulas. Adding a new kind of content later is a struct, a field and a validation rule.

## Context

- Tech design: "Content pipeline", "Designing for pivots" (Identity, Text and looks), "Library choices" (Content and validation, Formulas in content).
- CUE: https://cuelang.org/docs/integration/go/ and `go tool cue help get go`. `cue get go --local` generates CUE beside the Go types in this module.
- The CUE CLI is a Go tool here too (`go get -tool cuelang.org/go/cmd/cue@<the same version as the library>`), so every `cue` command in this task runs as `go tool cue ...` with nothing to install.
- Expr: https://expr-lang.org/docs/getting-started. Compile with `expr.Compile(src, expr.Env(T{}), ...)` and run with `expr.Run(program, env)`.

## Spec

**Shapes** (suggestions; keep the JSON names):

```go
// Bundle is the whole of content/data as decoded. Later tasks add fields.
type Bundle struct {
	Materials map[string]Material `json:"materials"`
	Terrains  map[string]Terrain  `json:"terrains"`
	Text      map[string]string   `json:"text"`
}

type Material struct {
	Name api.ContentID `json:"name"` // a text ID
}

// Terrain is what one cell of the world is made of: solid (clay, rock) or open (air, later water).
type Terrain struct {
	Name       api.ContentID `json:"name"`
	Solid      bool          `json:"solid"`  // blocks movement; can be stood on
	Opaque     bool          `json:"opaque"` // blocks sight
	FloorGlyph string        `json:"floor_glyph,omitempty"` // drawn when you stand on it
	WallGlyph  string        `json:"wall_glyph,omitempty"`  // drawn when it bounds open space
	Color      string        `json:"color,omitempty"`
	MoveCost   string        `json:"move_cost,omitempty"` // Expr with MoveEnv: ticks to walk on top of it; required when solid
}

// MoveEnv is everything a move_cost formula can see.
type MoveEnv struct {
	Encumbrance float64 `expr:"encumbrance"`
}
```

Data files are `package data`, import the generated package, and constrain each entry, for example `materials: [string]: content.#Material`. Keep the import path and the generated definition names as `cue get go` produces them.

**Loading:**

```go
func Load(dir string) (*Registry, error) // dir is content/data
```

1. Load the CUE package in `dir` with `cue/load`, build it with `cuecontext`, and validate it as concrete.
2. Decode into `Bundle` with `Value.Decode`.
3. Validate in Go, collecting every problem with `errors.Join` and naming the path of each:
   - every key matches the ID pattern and starts with its kind (`material.`, `terrain.`, `text.`);
   - every text reference points at an existing text entry;
   - every formula compiles against its environment and returns the right type.
4. Compute `Hash`: SHA-256 of `json.Marshal(bundle)`, which sorts map keys, as a hex string.

**Registry** (immutable once built; accessors return copies or values):

```go
type Registry struct{ /* bundle, compiled formulas, parsed templates */ }
func (r *Registry) Hash() string
func (r *Registry) Material(id api.ContentID) (Material, bool)
func (r *Registry) Terrain(id api.ContentID) (Terrain, bool)
func (r *Registry) TerrainIDs() []api.ContentID // sorted
func (r *Registry) MoveCost(terrain api.ContentID, env MoveEnv) (int64, error)
func (r *Registry) Render(t api.Text) string
```

- Formula fields are plain strings in the schema. The loader compiles them into a map inside the registry, keyed by owner and field, and typed accessors such as `MoveCost` run them.
- `Render` runs the text through `text/template` with `Args` as the data, caching parsed templates. A missing ID renders as `[missing text: <id>]` and never panics.

**Sample data:**

- Materials: `material.clay`, `material.flesh`.
- Terrains: `terrain.air` (open, not opaque) and `terrain.packed_clay` (solid, opaque, floor glyph `.`, wall glyph `#`, cost `1`).
- Text: their names, and `text.explore.bump`: "Packed clay. No way through."

## Acceptance criteria

- [x] `Load("content/data")` succeeds; `MoveCost("terrain.packed_clay", MoveEnv{})` returns 1.
- [x] A solid terrain without `move_cost` fails validation.
- [x] A bad ID, a dangling text reference and a formula that doesn't compile each fail with a message naming the path. Use table tests with inline CUE written to `t.TempDir()`.
- [x] Loading the same data twice gives the same `Hash`; changing one value changes it.
- [x] `Render` fills `{{.who}}`-style arguments and handles a missing ID.
- [x] `FuzzLoad` (fuzzed CUE text as one data file) never panics; run it for 30 seconds and note that in Notes.
- [x] `go tool task content` passes, and fails when a terrain drops a required field.
- [x] `go tool task schema` regenerates the `_go_gen.cue` files with no diff on a clean tree.

### Implementation notes (M1-06)

- **Schema generation:** `go tool cue get go --local` worked for a non-main package; the `cue.mod/gen` fallback was not needed.
- **Deviation, lower-case CUE module path:** CUE rejects upper-case module paths, but the Go path has `BemusedVermin`. `cue.mod/module.cue` is `github.com/bemusedvermin/achlydesa-heptarchy`, and the new `internal/tools/cuefix` rewrites the generated imports to match. `task schema` runs it after `cue get go`; data files import the lower-case path. `task schema` also generates `internal/core/api/*_go_gen.cue`, because the content schema imports `api.#ContentID`.
- **Solid without `move_cost`** is enforced in Go (`Load`), not in CUE, so `cue vet` alone does not catch it. Dropping a schema-required field (e.g. `opaque`) makes `task content` fail (checked by hand).
- **Formulas** compile with `expr.Env(MoveEnv{})` and `expr.AsInt64()`; a terrain without a formula costs 0.
- **Text templates** are parsed at load (a bad template fails with its path) and `Render` uses `missingkey=zero`, so a missing argument renders empty.
- **FuzzLoad:** ran 30s, no panics (about 470 execs; CUE loading is slow, roughly 11/sec).
- Files outside the list: `internal/tools/cuefix/`, `internal/core/api/*_go_gen.cue`, `go.mod`/`go.sum`, `tasks/INDEX.md`.
