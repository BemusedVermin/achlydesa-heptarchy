# M2-04.F1 · Check content IDs named by effect parameters at load

## Goal

An effect that names a content ID in a text parameter (`add_status` with `status.typo`, `consume` with an unknown item, `spawn_from_part` with an unknown faction, `attach_part` with an item that is not a piece) fails when `game.New` builds the world, not when the effect first runs in a fight.

## Context

- M2-04 registers those primitives. `effects.Validate` checks primitive names, parameter names and selector and formula syntax, but a `KindText` parameter is a literal it cannot check. Today the primitive returns an error from `Apply`, which makes the running game unusable.

## Deliverables

- A way for a primitive to check its literals against content at load, such as `Primitive.VerifyContent func(reg *content.Registry, raw map[string]string) error`, called by `effects.Validate`.
- The M2-04 primitives use it for status, item and faction IDs.
- A `game` test beside the existing bad-effects fixture.

## Spec

Suggestion only; keep `Verify` for rules that need no content.

## Acceptance criteria

- [x] `game.New` fails, listing the path, for each unknown status, item or faction an action's effects name.
- [x] `go tool task check` passes.

## Out of scope

- Checking IDs inside formulas.

## Notes

Added `Primitive.VerifyContent(reg, raw)`, run by `effects.Validate` after `Verify`. add_status, consume, spawn_from_part and attach_part use it (attach_part also requires the item to be a piece with a `part`). Fixture entries added to `internal/core/game/testdata/bad_actions.json`.
