# M5-07.F1 · Verify from chunk summaries, not the whole ground

## Goal

The verify stage reads a summary of each chunk's openings and joins them in a chunk graph, so a large world is checked without building every cell at once.

## Context

- `internal/core/worldgen/verify.go`: `repairWorld` lists every cell in the bounds, builds the ground before verify through `Context.Before`, flood-fills it and repairs it, once per source.
- M5-07's spec asked for a chunk graph built from per-chunk summaries, with A* on the chunk graph. The sample world is about 17,000 cells, so the whole-ground pass takes well under a second, but the large world (M5-06) is much bigger.

## Deliverables

- A per-chunk summary (areas with their border crossings) computed from `Context.Before`.
- Components and the nearest-area search on the chunk graph, then cells only along the chosen corridor.

## Spec

Same guarantees and the same results for the sample world's guarantees; the repair stays a pure function of the seed. Measure time and memory on the M5-06 world before and after.

## Acceptance criteria

- [ ] The guarantees test still passes, and peak chunks held at once stay bounded by a content-set limit.
- [ ] `go tool task check` passes.

## Out of scope

- Guarantees across an export: M5-10.

## Notes

Triaged 2026-11-25: todo in M5, so verify stays bounded on the large world before exports rely on it.

- How it works: verify reads the ground through its own `hexmap.Map` whose source drops the chunk loaded longest ago once it holds `max_chunks` (a new required verify param, 256 in `geography.cue`). Each chunk is flood-filled on its own into local areas; its summary keeps each area's size, whether it holds place cells, the cells of areas smaller than `min_pocket`, and its crossings into other chunks. A union-find over the summaries gives the walkable areas. After a repair, only the chunks an edit can reach are summarized again.
- Joining: a breadth-first search over chunks finds the shortest chain of chunks from the main area to any kept area; the corridor is then searched only in the chunks within 1 of that chain (then 2, then 4, then everywhere if none fits). The cell search is now A* over the same tunnel steps (a heap written in place; fzipp/astar takes one start and one goal, and this search has many of both). The chunk graph search is plain BFS, since every chunk step costs the same.
- Same guarantees, not the same edits: the repair is still a pure function of the seed, but areas are numbered in chunk order rather than cell order and the corridor search is A* within the chain's chunks, so a seed's carved corridors can differ from before. The rapid property and order-independence tests pass. The rapid property now also draws a `max_chunks` from 4 to 12 (the fixture world is about 12 chunks) and checks the peak never passes it.
- The property test runs 40 checks instead of 12: one check now takes about 0.15 s instead of 1.5 s. I deleted its stale rapid fail file under `testdata/rapid/`, which no longer matched the test's draws and made rapid run only that one case.
- `crossings` checks the way back with the one opposite direction instead of all six: a step changes the hex by exactly its direction, so only that one can lead back. Same result, six times fewer steps.
- `maxRepairRounds` (256) now counts on top of one round per area found at the start; the large world needs about 680 rounds.
- Measured on the M5-06 world (400 by 400 by 64, seed 1, `geography.deep` run by hand), 4 cores:
  - Before (whole ground): BEFORE_RESULT.
  - After, `max_chunks: 256`: 58 s, peak heap about 69 MB, peak 256 chunks. With 1024: 49 s, 109 MB.
  - About three quarters of the time is summarizing chunks: filling small pockets cascades (filling a pocket floors the open cells above it, making new pockets), so the first four rounds re-read nearly every chunk, and a sweep larger than the budget reloads each chunk through the earlier stages.
- Still too slow for a game's start, so `world.cue` keeps `geography.large` (no verify) and the large world has no guarantees yet: filed M5-07.F1.F1. The comments in `geography.cue` say so.
