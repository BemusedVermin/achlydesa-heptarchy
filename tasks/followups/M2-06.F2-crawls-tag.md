# M2-06.F2 · A crawls tag, so Stand freezes only the crawlers

## Goal

Stand delays only bodies that crawl, as the canon says: "In the deep, anyone who stands freezes everyone who crawls."

## Context

- `content/data/forms.cue`: Stand delays `others:all`, every other body in sight, as a stand-in until crawling is modeled.
- Rules 4 and 7: which bodies crawl is content, and selectors are the core's.

## Deliverables

- A `crawls` tag on bodies' templates (or parts) in content.
- A selector or an effect parameter that narrows a channel selection by a body tag, for example `others:all` filtered by a formula, in `internal/core/effects/selectors.go`.
- `action.stand` uses it. A test: Stand delays a crawler and not a person.

## Spec

Open design points: whether crawling is a template tag, a status (a body that has been knocked down crawls), or both. File a question if the design doesn't settle it.

## Acceptance criteria

- [x] Stand delays every crawling body in sight and no other.
- [x] `go tool task check` passes.

## Out of scope

- Factions and hostility (M2-07).

## Notes

The selector cannot read a tag today, so this needs a small Go change.

### Implementation notes

- Crawling is a template tag (`crawls`) for now; a status-based crawl (knocked down) is not modeled. Reversible: a later status could be read by the same selector.
- Body selectors take an optional template-tag filter, written `<set>[<tag>]`, such as `others[crawls]`. `action.stand` now freezes `others[crawls]:all`. This works in any body selector (`ParseBodies`), including channel selectors.
- No shipped person template crawls, so in play Stand freezes nobody until a crawler template exists. Added `template.test.crawler` (content/data/templates.cue) as the tagged example; the combat Stand test builds a crawler from the dummy with the tag.
- Files outside the list: `internal/core/combat/forms_test.go`, `internal/core/effects/effects_test.go`, `content/data/templates.cue`.
- Follow-ups filed: none.
