# M6-02.F1 · Let a template spawn an empty container

## Goal

Content can author a cistern or larder that starts empty and is still a container from the moment it spawns.

## Context

- `docs/game-design.md` → "Supplies are things in places": a container is something with a place and an inventory.
- `internal/core/inventory/inventory.go` (`spawnInventory`) adds `comp.Inventory` only through `Add`, and `Add` skips empty stacks. A template with no `inventory:` (or an empty one) spawns without `comp.Inventory`, so it is not a container until someone puts something in it.
- `content.Template.Inventory` is `[]StackDef` with `omitempty`, so CUE cannot tell "no inventory" from "an empty one".
- The sample `template.container.cistern` and `template.container.larder` in `content/data/templates.cue` start with five items each to get around this.

## Deliverables

- `internal/content/types.go`: a way for a template to say it is a container with nothing in it (for example `container: true`, or `inventory` as a pointer to a struct holding the stacks).
- `internal/core/inventory/inventory.go`: the spawner gives such a template an empty `comp.Inventory`.
- Regenerated schema; the sample cistern may then start empty.

## Spec

- An empty container spawns with `comp.Inventory{}` and `Pos`. Nothing else changes.

## Acceptance criteria

- [x] A template marked as an empty container spawns with an empty `comp.Inventory`.
- [x] `go tool task check` passes.

## Out of scope

- Towns placing containers: M6-22.
