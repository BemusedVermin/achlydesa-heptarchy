# M5-09.F1 · Stop TestWatchOneCallbackPerBurst flaking on a loaded CI runner

## Goal

`TestWatchOneCallbackPerBurst` passes every time, including on a slow runner.

## Context

- `internal/content/watch_test.go:17`, with `testDebounce = 40ms`.
- It failed once on the first CI run of PR #180 ("a burst produced more than one callback"), a change that doesn't touch the watcher, and passed 20 of 20 locally and on the rerun after merging master.
- The five writes can straddle the 40 ms debounce when the runner stalls, which yields two callbacks.

## Deliverables

- `internal/content/watch_test.go`: a debounce long enough that the writes can't straddle it (for example 500 ms), or an assertion that doesn't depend on writes landing inside one window.

## Spec

Test-only change. The debounce behavior stays as it is.

## Acceptance criteria

- [x] `go test -count=50 -run TestWatchOneCallbackPerBurst ./internal/content` passes.
- [x] `go tool task check` passes (see Notes).

## Out of scope

- Changing the watcher itself.

## Notes

The burst test now uses its own 500 ms debounce (`burstDebounce`), so five back-to-back writes can't straddle it; the other watch tests keep 40 ms to stay fast. 50 of 50 runs pass (about 1.5 s each).

Golangci-lint could not run in this sandbox (the installed binary was built with an older Go than the module targets), so lint and fmt-check are left to CI. gofmt, go vet, the package tests and the comments check pass.
