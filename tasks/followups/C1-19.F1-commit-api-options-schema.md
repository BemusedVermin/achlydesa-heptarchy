# C1-19.F1 · Commit the generated schema for api/options.go

## Goal

`go tool task schema` on master leaves the tree clean, so a task that runs it commits only its own schema changes.

## Context

- `.claude/rules/content.md` and `.claude/rules/core.md`: after changing a struct or constant in `api`, `comp` or `content`, run `go tool task schema` and commit the regenerated files.
- C1-18 (#96) added `internal/core/api/options.go` (the timeline entry kinds and the option ID prefixes) without regenerating. On master, `go tool task schema` now writes a new untracked `internal/core/api/options_go_gen.cue` holding `#EntryReady`, `#EntryLands` and the `#Option...Prefix` constants.
- C1-19 ran the schema task and deleted that file again rather than commit a change to `api` outside its area.

## Deliverables

- `internal/core/api/options_go_gen.cue`: generated by `go tool task schema`, committed.

## Spec

Run `go tool task schema` on master and commit the one new file. Nothing in `content/data` uses the constants yet, so `go tool task content` stays green.

## Acceptance criteria

- [ ] `go tool task schema` on the branch leaves `git status` clean.
- [ ] `go tool task check` passes.

## Out of scope

- A check in CI that the schemas are up to date: that is lock-in work (C1-27) if the owner wants it.
