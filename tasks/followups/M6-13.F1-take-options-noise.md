# M6-13.F1 · Hide take options for items the thing does not hold

## Goal

The player's menu lists a take only for items the source or container holds, and a put only into a thing that has room, instead of a disabled option for every ware.

## Context

- `action.take` offers every ware (the `ware` choice) for every source or container in reach; one the thing lacks comes out disabled with `text.actions.none_there`. Next to a well that is a disabled "Take ration" beside the real "Take water".
- Choices are offered per actor (`internal/core/actions/choices.go`), so they cannot see the target.

## Deliverables

- `internal/core/actions/`: drop an intent from the options when an effect's check says the target can never give the choice (an `Impossible` kind of refusal), or offer choices per target.
- A test that a well offers no ration.

## Spec

Whichever route is taken, an agent's picker and the player's menu must keep agreeing on what is startable.

## Acceptance criteria

- [x] Next to a well the menu has take water and no take ration.
- [x] `go tool task check` passes.

## Out of scope

- Container capacity: containers have no cap today, so only a source can be full.

## Notes

Triaged 2026-11-27: todo in M6.

- Route: the first one. `effects.Primitive` has a new optional `Impossible` hook (and `effects.Impossible`); `actions.evaluate` drops a plan any of whose effects says it is impossible, so the menu, `Startable` and `Validate` keep agreeing. A command naming such an intent is rejected with the effect's reason.
- `inventory.CheckTransfer` has two new refusals: `Absent` (the giver neither holds the item nor is a source of it) and `Unsuited` (a put into a source of another item, which was `Full` before). `Refusal.Impossible` covers both; take and put use it.
- Decision: a container that holds none of a ware right now hides that take, as the Goal says, though it could hold some later. A source of the item that is empty or full stays offered disabled, with its reason, since it refills.
- Puts into a source of another item are hidden too (a put of ration into a well), not only takes.
- `Unsuited` still reads as `text.actions.no_room`, as the old `Full` did; it now only shows when a command is rejected.
- Files outside the Deliverables: `internal/core/effects/effects.go`, `internal/core/inventory/source.go`, `docs/content-guide.md` (one sentence on which takes and puts are offered).
- No follow-ups filed.
