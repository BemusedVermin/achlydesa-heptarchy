# C1-23.F1 · Move the hot reload's log messages into content text

## Goal

The two lines a dev-build content reload writes to the message log come from content text, like every other line the player reads.

## Context

- `internal/core/game/game.go`, `SwapContent`: `g.Note("content reloaded: a replay from before this point will not match")` is English in Go.
- `cmd/heptarchy/main.go`, the `content.Watch` callback: `fmt.Errorf("content reload failed, keeping the old content: %w", err)`, which the tui writes to the log through `Game.Note`. C1-23 moved this line out of the tui, but it is still English in Go.
- AGENTS.md rule 4 and `.claude/rules/core.md`: player-facing text leaves the core as an `api.Text`.
- Both appear only with `--dev`, which is why C1-23 left them.

## Deliverables

- Text records such as `text.game.content_reloaded` and `text.game.reload_failed` (with an `{{.error}}` argument).
- `SwapContent` renders the first; a `Game` method (or `Note` taking an `api.Text`) renders the second, so `cmd/heptarchy` passes only the error.

## Spec

Most reversible shape: keep `Note(string)` for callers that already hold rendered text, and add `NoteText(api.Text)` for these two.

## Acceptance criteria

- [x] `grep -rn "content reload" internal cmd --include=*.go` finds no English sentence outside tests.
- [x] `go tool task check` passes.

## Out of scope

- Any other dev tooling text (cobra help, flags), which is the frontend's own.

## Notes
- Triaged 2026-11-23: folded into C1-23, as the owner asked; done in PR #107. The texts are `text.game.content_reloaded` and `text.game.reload_failed`, rendered by `SwapContent` and a new `Game.ReloadFailed(err)` through `Game.NoteText`, so the tui calls one method and `cmd/heptarchy` passes only the error.
