# M2-13.F1 · Test CUE constraints against the real schema

## Goal

Constraints that live in CUE, such as the one that a material's weakness can't also be its immunity (`content/data/materials.cue`), have a Go test that fails when the constraint stops holding.

## Context

- M2-13 moved that rule out of Go. It was checked once by hand (`go tool task content` with an overlapping fixture); no test covers it.
- `content` tests load data from a temporary directory, which has no `cue.mod`, so a copy of `content/data` can't import the schema there.

## Deliverables

- A test helper that copies `content/data` into a temporary directory together with a `cue.mod/module.cue` that resolves the schema import (or a `cue.mod` override in `load`), and a test that adds an overlapping material and expects `Load` to fail.

## Spec

Suggestion: let `loadBundle` accept a module root, or have the test build a temp tree holding a symlink or copy of `internal/content` and `cue.mod`.

## Acceptance criteria

- [x] A weakness that is also an immunity makes `content.Load` fail in a test.
- [x] `go tool task check` passes.

## Out of scope

- Moving other checks between Go and CUE.

## Notes

Filed by M2-13; done in the same PR at the owner's request. `internal/content/schema_test.go` copies the repository's CUE (cue.mod, the generated schemas, content/data) into a temp module root, checks the copy loads, then makes flesh immune to a type it is weak to and expects `Load` to fail on the `_overlap` constraint. No loader change was needed.
