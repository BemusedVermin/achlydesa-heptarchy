# M3-11.F1.F1.F1 · Report TownEmptied for a town off screen whose resident bodies leave or die

## Goal

A town the party is not in reports `TownEmptied` once when its last resident goes, whether the residents are counted in its region or stand on its map as bodies.

## Context

- `docs/game-design.md`, "World and towns": a town counts as emptied when its last resident leaves or dies, wherever the party is.
- `internal/core/agents/emptied.go`, `publishIfEmptied`, reports only for the party's own map.
- `internal/core/agents/offscreen.go`, `applyPlan`, reports only when the region's count drops from above 0, and ignores bodies.
- At the start, bodies are spawned on every map but only the start map is promoted, so an unvisited town may hold resident bodies while its region count is 0. If all of them leave or die, neither path reports it.

## Deliverables

- One definition of "residents left" that counts region population and live bodies together, used by both paths.
- A test with an unvisited town whose resident bodies leave, and one where they die, each reporting once, and one where the tick and a body leaving cannot report the same town twice.

## Spec

Dropping the party guard in `publishIfEmptied` alone is not safe: the tick can fire on a population drop while bodies still stand on the map, and a later body check would report the town a second time. Settle the single definition first. Whether off-screen bodies take turns in real play is unchecked.

## Acceptance criteria

- [ ] An unvisited town emptied by bodies leaving, and one by bodies dying, each report `TownEmptied` once.
- [ ] No town reports `TownEmptied` twice.
- [ ] `go tool task check` passes.

## Out of scope

- Generic NPC replacement (M3-12).
