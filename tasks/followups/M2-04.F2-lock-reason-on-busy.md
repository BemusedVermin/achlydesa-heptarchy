# M2-04.F2 · Tell a lock from ordinary busy time

## Goal

The effect variable `locked` is true only while a channel is held busy by a `lock` effect, not while it recovers from its own action.

## Context

- M2-04 spec: `Locked` is "whether the target part is busy because of a lock". `comp.Busy` holds only an `Until` tick, so M2-04 reports `locked` as "the part is busy for any reason".
- Pin's design reads as a lock (the part is held), but Stand-style formulas may want to tell a held arm from a swinging one.

## Deliverables

- `comp.Busy` records whether the last change to it was a lock (a `Locked bool`), or `lock` writes a second component.
- `effects` env sets `Locked` from that; `timeline` keeps the flag consistent when busy time is occupied, extended or released.
- A test: a swinging arm reports `locked` false; a locked arm reports true.

## Spec

Firm: `locked` means "held by a lock". How the flag is stored is open.

## Acceptance criteria

- [ ] `locked` is false for a channel busy only from its own action's recovery.
- [ ] `locked` is true after the `lock` effect, until the busy time ends or `ready` frees it.
- [ ] `go tool task check` passes.

## Out of scope

- New timing primitives.
