# M1-20.F2 · Cell-targeted actions

## Goal

An action may target a cell (`target: "cell"`) and range over cells, so things like throwing, digging at a distance or placing something are expressible in content.

## Context

- M1-20 lets content name `target: "cell"` but `actions.Intent`, `api.Do` and `effects.Context` carry no cell, so no option is ever offered and `Validate` refuses it.

## Deliverables

- A `Cell *api.Cell` on `Intent`, `api.Do`, `comp.Landing` and `effects.Context`.
- Cell enumeration in `actions` (cells within range, in sight when required) and a cell segment in option IDs.

## Spec

Reuse `hexmap.Map.CellsIn` and the sight set `actions` already caches. Keep option order: action key, choices, then cell by (depth, q, r).

## Acceptance criteria

- [ ] A cell-targeted test action is offered once per cell in range and sight, and lands on the chosen cell.
- [ ] `go tool task check` passes.

## Out of scope

- Which game actions use cells; that is design.

## Notes

Triaged by the owner: parked as unplanned until a game action needs cells.
