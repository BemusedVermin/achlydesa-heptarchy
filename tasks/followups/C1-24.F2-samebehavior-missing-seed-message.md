# C1-24.F2 · samebehavior says clearly when a seed reports no hash

## Goal

When the working tree's harness log has no final hash for a seed the base reported, samebehavior's report says so instead of printing an empty hash.

## Context

- `internal/tools/samebehavior/main.go`, `compareHashes`: for a seed missing from `got` it prints `seed 2 ends at , was 00bb`.
- C1-24 added table tests of `compareHashes` but left this case out, so as not to pin the poor message.

## Deliverables

- `compareHashes` reports a missing seed as, for example, `seed 2 reported no hash, was 00bb`.
- A case for it in `TestCompareHashes`.

## Spec

Only the message for a seed whose hash is missing in the working tree changes. Other messages stay as they are.

## Acceptance criteria

- [ ] `TestCompareHashes` has a missing-seed case with the new message.
- [ ] `go tool task test -- ./internal/tools/samebehavior` passes.

## Out of scope

- Other changes to samebehavior's report.
