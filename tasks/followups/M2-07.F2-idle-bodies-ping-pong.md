# M2-07.F2 · Idle bodies waiting on each other move time on a tick at a time

## Goal

A world with two or more non-player bodies that do nothing must not need one decision per tick while the player is busy or waiting for a far-off tick.

## Context

When a controller neither occupies a channel nor waits, `timeline.state.decide` makes the body wait until `nextOtherEntry` (`internal/core/timeline/timeline.go`), which is the earliest other live entry but never before the next tick. With the party's follower and a creature using the built-in `idle` controller, each one's next other entry is the other's, one tick on, so they alternate a tick at a time until the player's far-off slot (for example a phase wait of hundreds of ticks) is reached. `harness` hit `timeline: 10000 decisions passed without the player acting` as soon as M2-07 put a creature on the hall map.

M2-07 works around it with a `rest` controller (`internal/core/combat/rest.go`) that occupies the body's channels for `combat.rest_ticks`, but any other waiting body (a future seat or follower) has the same problem.

## Options

1. Have `nextOtherEntry` skip entries of bodies that are themselves only waiting (an entry whose body made no change last decision), so waiting bodies sleep until something that can act is due. Small, but "only waiting" needs tracking.
2. Give `idle` a configured sleep (a `timeline` content number) like `rest`. Simple; one more number to tune.
3. Leave it and rely on real controllers (M2-08). Cheapest, but the trap stays for the next idle body.

## Recommendation

Option 1, with a test of two idle bodies and a player waiting a phase.

## Acceptance criteria

- [x] A test with two idle bodies and a player who waits for the next phase finishes in a handful of decisions.
- [x] The `rest` controller from M2-07 can then be removed, or kept if M2-08 still wants it.

## Out of scope

- Creature behavior (M2-08).

## Notes

Filed by M2-07.

Triaged by M2-15: todo in M2, because M2-08 and M2-09 add more waiting bodies (creatures, grafts), and the harness already hit the 10000-decision limit with two.

Implemented option 1: `timeline` keeps a `sleeping` set (bodies whose last decision only waited); `nextOtherEntry` skips them; a body leaves the set when popped or when it changes something. The set is saved as `Saved.Sleeping` (omitempty) so a load continues identically. Test: `sleep_test.go`. The `rest` controller is kept: M2-08 may still want it, and removing it is a content change for the sample creature. No follow-ups filed.
