# M1-10.F1.F1.F1 · Plan view: do not recompute reachability on every view build

## Goal

`View()` stops running a breadth-first flood over the map each time it is built when nothing it depends on has changed.

## Context

- M1-10.F1.F1 made `buildMap` in `internal/core/explore/project.go` call `hexmap.Map.Reachable` on every view build, up to `party.plan_range` steps (12 to start) over seen cells, six `Step` calls per cell.
- It is cheap at the current range and map sizes. It scales with the range squared, and the harness and the terminal rebuild the view often.

## Deliverables

- Cache the reachable set against the focus cell, the seen set's size and the step rules; or measure first and close this if the cost is negligible.

## Spec

Measure with a benchmark at a range of 12 and of 30 before caching. Cached state must live on the world (a resource), be rebuilt after a load, and never decide an outcome, only the view.

## Acceptance criteria

- [ ] A benchmark shows the cost, or the cache removes it.
- [ ] `go tool task check` passes.

## Out of scope

- Reachability across map links (M1-14.F1).

## Notes

Filed by M1-10.F1.F1.
