# C1-21.F1 · Stop reparsing the sample content in every combat test

## Goal

The combat package tests run well under 10 seconds on a busy laptop, not just on an idle one.

## Context

- C1-21 cut `TestRandomFightsKeepTheInvariants` from about 48s to about 2s, but the whole package still took 13 to 37s on an 8-core laptop shared with other agents' tests, with about 10s for `-short`, which skips the property test.
- A CPU profile of `go test -short ./internal/core/combat` puts about 18% in `content.LoadBundle`: `newRig`, `newRing` and `newField` (`internal/core/combat/effects_test.go`, `forms_test.go`, `sides_test.go`) each call `contenttest.SampleBundle`, which parses the CUE again for every test. About 30% is `game.View` (option evaluation in `actions.usableChannels`), which is engine cost.
- C1-13 decided tests may share only the immutable registry, not a bundle.

## Deliverables

- A way for tests to get a fresh, mutable sample bundle without reparsing CUE.

## Spec

Suggestion: `contenttest.SampleBundle` loads the bundle once and returns a deep copy each call (a JSON round trip of `content.Bundle`, checked by a test that the copy builds a registry with the same `Hash` as the loaded one). Each test still owns its bundle, so C1-13's rule holds. If the owner reads C1-13 as forbidding this too, the alternative is to build the per-fixture registries once per package for fixtures that take no mutation.

## Acceptance criteria

- [x] `go test ./internal/core/combat` takes measurably less time, with the same tests.
- [x] `go tool task check` passes.

## Out of scope

- Speeding up option evaluation in `actions`: engine work, not test work.

## Notes

- Triaged 2026-11-23: todo in C1, as the owner decided; C1 is the cleanup of tests that cost more than they protect.
- Done as the spec suggested: `contenttest.SampleBundle` parses once and returns a JSON-decoded copy per call. Tests check the copy builds a registry with the loaded hash and that copies are independent. Only `internal/content/contenttest` changed.
- The combat package ran in about 9s with `-short` (about 10s before); timings on this shared machine are noisy, and the rest is engine cost (`game.View`).
- `check-pr` fails on this branch: a `test` task may change only `_test.go` files, but `contenttest.go` is not one. C1-21.F2 would let check-pr accept this; the owner decides whether to wait for it.
