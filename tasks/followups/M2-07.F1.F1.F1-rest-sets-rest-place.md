# M2-07.F1.F1.F1 · Resting in a town sets the party's rest place

## Goal

When the party rests in a town, `explore.SetRestPlace` is called with that town's cell, so a later wipe wakes it there.

## Context

M2-07.F1.F1 added `comp.RestPlace` on the party, set once to the opening cell by `explore.Start`, and `explore.SetRestPlace` to move it. No town or rest action exists yet, so nothing calls the setter. See `internal/core/explore/wake.go`.

## Deliverables

- The town's rest action (or the rest effect) calls `SetRestPlace`.
- A test that rests in a town, wipes the party and checks the wake place.

## Spec

Depends on towns and a rest action existing (M3). Which feature package owns the call is open: explore may not import a town package, so the rest action should publish an event that explore handles, or write the component itself.

## Acceptance criteria

- [ ] A party that rests in a town and is then wiped wakes in that town.
- [ ] `go tool task check` passes.

## Out of scope

- What the enemies did meanwhile, and whether dead members return (design questions in M2-07.F1.F1's Notes).
