# C1-26.F1 · Use "move" only for movement in game-design.md

## Goal

`docs/game-design.md` uses "move" the way `docs/glossary.md` defines it: movement across the map only, never an action in general.

## Context

- `docs/glossary.md`: "**move**: movement across the map (`api.Moved`, `move_cost`); never form x type."
- C1-26 fixed the same misuse in the Genre line (`game-design.md:12`), which its Spec covered; these lines were outside it.

## Deliverables

- `docs/game-design.md`: the three passages below reworded.

## Spec

- `:107` "Exploring and fighting both happen on the hex grid, on the same clock; moves are picked from menus." becomes "...; actions are picked from menus."
- `:372` "**Moves come from menus.** The player positions a member on the grid, then picks the action, type and target from a menu." becomes "**Actions come from menus.** ..."
- `:373` "A move reaches only what's in sight and in range." becomes "An action reaches only what's in sight and in range."

Line numbers are as of C1-26; search for the quoted text.

## Acceptance criteria

- [ ] `docs/game-design.md` uses "move" only for movement across the map.
- [ ] Only `docs/` changed.

## Out of scope

- "move" in code and content, which already follow the glossary.
