# M6-10.F1 · Decide whether a has fact names an item or an item tag

## Goal

Settle what the `tag` of a planner's `has` fact names, before M6-13's operators and M6-25's wants depend on it.

## Context

- `internal/content/minds.go`, `checkCondition`: a `has` condition's tag must be an `item.` ID, and `agents.StateOf` counts carried stacks of that item.
- The task said `has(tag, n)` without saying which. M6-25 speaks of "item tags the person wants", which reads as matching by tag.
- Content today has `item.water` and `item.lake_water`: with item IDs, an operator to drink needs one per item; with tags, one operator meets "anything tagged drinkable".

## Deliverables

- The decision recorded in `docs/game-design.md` ("How minds work") and, if it changes, the loader and `StateOf`.

## Spec

Options:

1. **Item IDs (as built).** Exact and simple; the loader checks the ID. Costs one operator per item that meets a need, and wants name items, not kinds.
2. **Item tags.** `has(drinkable, 1)` counts every carried item tagged `drinkable`, closed by `vocabulary.tags.items`. One operator serves many items; a plan's take or consume step then needs a picker to choose which item.
3. **Either, by prefix.** An `item.` ID matches that item, a bare word matches a tag. Most flexible, two meanings in one field.

Recommendation: 2, since wants and recipes read as kinds of thing, and the vocabulary already closes item tags. The change is small while no operators exist.

**Decided by the owner:** option 2, item tags. A `has` fact names a tag from `vocabulary.tags.items`, and holds when the agent carries at least `n` items in all with that tag. The loader checks the tag against the vocabulary instead of requiring an `item.` ID, and `agents.StateOf` counts carried stacks by tag. Sample content that names an item in a `has` fact changes to a tag. The picker for take and consume steps is M6-13's.

## Acceptance criteria

- [x] The decision is recorded in the design doc and the content guide.
- [x] `go tool task check` passes.

## Out of scope

- The operators themselves: M6-13.

## Notes

- The loader checks a `has` tag against `vocabulary.tags.items`, closed or not: with no item tags declared, no `has` fact loads.
- Added `drinkable` and `edible` to the vocabulary and tagged `item.water` and `item.ration` with them, so the content guide's example works.
- The docs already carried the decision; no doc change.
