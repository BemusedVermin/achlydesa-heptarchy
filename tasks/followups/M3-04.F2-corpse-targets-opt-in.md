# M3-04.F2 · Let an action say whether it may target a corpse

## Goal

Which actions may be aimed at a dead body is content, not an accident of how options are listed.

## Context

- A dead body loses `comp.Actor`, so no body-targeted action could name it. `consume` needs to eat a corpse, so M3-04 made `evaluator.isBody` in `internal/core/actions/actions.go` accept a body with `comp.Dead`.
- Corpses are still never listed by `Startable` or `Options`, but any hand-built intent naming one now passes target checks for every body-targeted action, strikes included.

## Deliverables

- An `ActionDef` flag (name to decide, for example `corpse`) that allows a dead target, with `isBody` reading it.
- Regenerated schemas, and the gnaw test action marked.

## Spec

Without the flag an action refuses a dead target as `bad_target`. With it, the action accepts a living or a dead one.

## Acceptance criteria

- [x] An unflagged action refuses a corpse; the flagged test action accepts it.
- [x] `go tool task check` passes.

## Out of scope

- Listing corpses as options for the player.

## Notes

- The flag is `corpse` (`ActionDef.Corpse`), applying to `body`, `ally` and `part` targets. Only `action.gnaw` sets it; no shipped action did before, so no player-facing behavior changes.
- Shown by `TestOnlyACorpseActionMayTargetADeadBody` in `internal/core/actions/actions_test.go`; the M3-04 consume test in `agents` still passes. `go tool task check-ci BASE=origin/master` passes.
- Docs: added a paragraph on `corpse` to `docs/content-guide.md`.
- No follow-ups filed.
