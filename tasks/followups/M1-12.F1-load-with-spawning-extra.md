# M1-12.F1 · Let Load run a Config.Extra that spawns

## Goal

`game.Load` works with the same `Config` as `game.New`, including tests whose `Extra` spawns an actor, instead of failing because the world is not empty.

## Context

- `Config.Extra` runs after install and before the scheduler freezes. Tests use it to spawn actors in place of the start scenario.
- ark-serde needs an empty world, so `Load` fails with "does Config.Extra spawn entities?" when `Extra` has spawned something.
- M1-12 left it as a documented limit: the save tests use the start scenario and an `Extra` that only records the world.

## Deliverables

- A way to separate what `Extra` installs (hooks) from what it spawns, such as a second `Config` field for spawning that `Load` skips, and the existing tests moved over.

## Spec

Choose the smallest split that keeps `New` behaving as it does now. A suggestion: `Config.Install` for hooks, run by both `New` and `Load`, and `Config.Spawn` for entities, run by `New` only.

## Acceptance criteria

- [x] A test with an `Extra`-style fixture that spawns an actor saves and loads with the same hash.
- [x] `go tool task check` passes.

## Out of scope

- The save format itself (M1-12).
