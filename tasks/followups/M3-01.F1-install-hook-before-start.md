# M3-01.F1 · Run game.Config.Install before the start map spawns its bodies

## Goal

A test or harness hook can register a controller or chooser that a map's own bodies name, so content can be tried with Go-side registrations without spawning bodies by hand.

## Context

- `internal/core/game/game.go`, `build`: the scenario (`explore.Start`, which spawns every map's marked bodies) runs before `cfg.Install`. The `Config.Install` doc comment says it runs "after the standard packages are installed", which is true, but a reader expects it to come before anything spawns.
- A body whose template names a controller or chooser that only `Install` registers fails to spawn: `timeline`'s `actor` spawner and `actions`' `chooser` spawner both refuse unknown names.
- M3-01's tests in `internal/core/combat/delegation_test.go` work around it by spawning a stand-in body after the game starts.

## Deliverables

- `internal/core/game/game.go`: `cfg.Install` runs before the scenario in `build`, or its doc comment says it runs after the start map is spawned.
- A test that a start-map body may name a controller registered in `Install`, if the order changes.

## Spec

Either order is fine as long as the doc comment says which. Moving `Install` earlier must keep `same-behavior` unchanged on the default seeds, and `Load` must still run it before the save's entities are restored.

## Acceptance criteria

- [ ] The doc comment on `Config.Install` says whether bodies already exist when it runs.
- [ ] `go tool task same-behavior` reports no behavior change.
- [ ] `go tool task check` passes.

## Out of scope

- New registration hooks for content validation.
