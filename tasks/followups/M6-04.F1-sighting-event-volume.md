# M6-04.F1 · Keep agents' sightings from flooding the event bus

## Goal

Agents re-sensing the bodies around them don't publish an event per fact per look, so 1,000 near agents stay under the bus's cascade limit and don't spend their budget on events nobody reads.

## Context

- `internal/core/knowledge/knowledge.go`: `Learn` publishes `api.FactLearned` for every fact it keeps, including a sighting that only refreshes the tick of a belief it already held.
- `internal/core/agents/sense.go`: `sense` learns one or two facts per body in sight, every time an agent looks.
- The bus refuses a drain past 10,000 events (`sim: event cascade exceeded 10000 events`). `BenchmarkThousandAgentsSenseOnce` in `internal/core/agents/sense_test.go` hit it when all 1,000 agents sensed before one drain, and now drains after each agent.
- Nothing subscribes to `FactLearned` today; M6-18 (hearsay) and the harness may.

## Deliverables

- `internal/core/knowledge/`: either no `FactLearned` when a fact comes back with the same value and only a newer tick, or a way for `sense` to learn without publishing (for example a `Refresh` that only restamps).
- A test that re-sensing an unchanged scene publishes nothing.

## Spec

- A changed value, a new fact, or a fact the party learns still publishes as today.
- Pick whichever of the two shapes keeps `Learn`'s callers simplest.

**Decided by the owner:** only emit `FactLearned` on actually learning a new fact. A fact that is already known publishes nothing, whether a sighting only refreshes its tick or repeats its value. Where this narrows the Spec line above: a new fact (no existing one for that subject, claim and source) publishes, and a fact that is already known does not. A changed value of a known fact is left to the implementer, who says in Notes which way it went and why.

## Acceptance criteria

- [ ] Re-sensing an unchanged scene publishes no `FactLearned`.
- [ ] `go tool task check` passes.

## Out of scope

- How a mind reacts to what it learns: M6-10 onward.
