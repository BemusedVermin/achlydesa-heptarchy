# M3-02.F1 · Decide what happens to a body's need when hot-reloaded content drops it

## Goal

Hot reload keeps working when a designer deletes or renames a need that live bodies carry.

## Context

- `internal/core/agents/needs.go` (`tickNeed`): a body whose `comp.Needs` names a need the registry no longer has makes the per-phase system return `unknown need`, which breaks the game at the next phase boundary.
- `internal/core/game/game.go` (`SwapContent`) swaps the registry between ticks and does not touch components.
- Saves are disposable, so loading is not the concern; only a live swap is.

## Deliverables

- A rule for stale levels on swap, in `agents` (a hook `SwapContent` runs, or the tick skipping them), and a test.

## Spec

Options:

1. Drop levels of unknown needs when content is swapped. Cheap; the body forgets the need.
2. Keep them but skip them in the tick and in `BodyEnv.Needs`. Keeps the level should the need come back.
3. Leave it an error, as today. Strict, but a rename during play needs a restart.

Recommendation: 2, because it loses nothing and needs no swap hook.

## Acceptance criteria

- [x] Swapping to content without `need.water` while a body carries it lets the game play on past a phase boundary.
- [x] `go tool task check` passes.

## Out of scope

- Template changes to which needs new bodies start with: they take effect at spawn already.

## Notes

Triaged 2026-11-24: todo in M3, because hot reload during need play would otherwise stop the game.

Chose option 2: `tickNeed` and `BodyEnv.Needs` skip needs the registry lacks; the level stays on the body. No swap hook.
