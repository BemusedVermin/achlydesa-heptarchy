# M2-06.F3 · Let body-wide damage read each part's weakness

## Goal

Sweep's `damage(parts: "target:all", amount: weak ? 2 : 1)` hurts each part by its own weakness, so lake water with Sweep wears down every clay part harder than the flesh around it.

## Context

- `weak`, `immune`, `integrity` and the other part variables describe the target part, and a Sweep has none, so `weak` is always false there and every part takes 1.
- Game design: "Combat → Types" example moves (lake water with Sweep douses every clay part).
- M2-06 refuses a body-aimed move only when every part is immune; it does not look at weakness per part.

## Deliverables

- The effect core evaluates a primitive's formulas once per selected part, with that part as the target part, when the selector picks parts.
- A test: a Sweep of Soak on a body with a clay part and a flesh part hurts them by 2 and 1.

## Spec

Suggested: when `damage` (and later part primitives) resolve `parts`, run `amount` with each part as `TargetPart`. Keep `roll` drawn once per effect, not per part, so the stream stays predictable.

## Acceptance criteria

- [x] A Sweep with a type some parts are weak to hurts those parts more than the others.
- [x] `go tool task check` passes.

## Out of scope

- Changing the form numbers.

## Notes

Filed by M2-06. Started on the owner's say-so with M2-06 in the same PR.

Added `Params.IntForPart(name, part)`: it evaluates a formula with that part as the target part, and every call of one effect shares a single roll (drawn on first use), so the RNG stream draws once per effect. `damage` now works out `amount` per selected part (an invalid formula on an empty selection is no longer evaluated; formulas are still compiled at load). Part primitives added later can use the same method. Test: `TestSweepHurtsEachPartByItsOwnWeakness` (Soak Sweep on a crawler: clay core loses 2, flesh parts 1).
