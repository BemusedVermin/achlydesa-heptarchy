# M1-16.F2 · Show the party's control mode and alert in the view

## Goal

`PartyView` says whether the party is in follow or individual mode, and whether an alert is on, so a frontend can draw a status line rather than guess from which options exist.

## Context

- M1-16 keeps the mode in `comp.Party.Control` and offers `control/follow` or `control/individual` as options, but `PartyView` does not carry either the mode or the alert.
- M1-11 (the terminal frontend) is the first consumer; M2-07 sets `Alert`.

## Deliverables

- `internal/core/api/explore.go`: `PartyView` gains `Control` and `Alert`.
- `internal/core/explore/project.go`: fills them.

## Spec

`Control string` is `follow` or `individual`; `Alert bool`. Plain data, no behavior.

## Acceptance criteria

- [ ] The view shows the mode before and after `explore.control`, and the alert when forced.
- [ ] `go tool task check` passes.

## Out of scope

- How a frontend draws them (M1-11).

## Notes

Obsolete: merged into M2-07, which sets `Alert` and now also adds `Control` and `Alert` to `PartyView`. Triaged by the owner.
