# M3-13.F1 · Let an action's requires formula see whether the party is on alert

## Goal

`action.eat` and `action.drink` are refused while a hostile is in sight, as M3-13's spec asks, with the rule written in content.

## Context

- M3-13 says eating and drinking are available "while not in a fight's reach". `content.ActionEnv` and `BodyEnv` carry no alert fact, so the actions only require the item (`content/data/actions.cue`).
- `comp.Party.Alert` holds the fact (`internal/core/explore`).

## Deliverables

- A field on `BodyEnv` or `ActionEnv` (for example `source.alert`) filled from the body's party.
- `requires` on `action.eat` and `action.drink` reads it.

## Spec

Suggestion: `BodyEnv.Alert bool`, false for a body outside a party. Foundation code (`effects/env.go`) reads `comp.Party` through `anatomy.PartyOf`.

## Acceptance criteria

- [ ] With a hostile in sight, the eat and drink options are disabled with a reason.
- [ ] `go tool task check` passes.

## Out of scope

- Whether eating mid-fight should ever be allowed (a design question).
