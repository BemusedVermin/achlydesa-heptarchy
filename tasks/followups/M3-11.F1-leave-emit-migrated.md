# M3-11.F1 · Emit Migrated when a resident leaves to an off-screen map

## Goal

A resident that crosses a gate to an off-screen region is counted there and removed, and the world says so with the same `Migrated` event the off-screen tick emits.

## Context

- `internal/core/agents/leave.go`, `crossGate`: it adds the body to the destination region's `comp.Populations` and despawns it, but publishes nothing, because `api.Migrated` is M3-10's and did not exist when M3-11 was written.
- M3-10's Deliverables add `Migrated`, `TownEmptied` and `PopulationDied`.

## Deliverables

- `crossGate` publishes `api.Migrated` for the family, the source and destination maps and a count of 1.
- A line in `residents_test.go` checking the event.

## Spec

Suggestion: reuse M3-10's event and payload unchanged. If M3-10 emits `TownEmptied` from its own tick only, decide whether an on-screen town losing its last resident should too.

## Acceptance criteria

- [x] A resident leaving to an off-screen map publishes `Migrated`.
- [x] `go tool task check` passes.

## Out of scope

- Changing M3-10's drift.

## Notes

- `Short` is left empty on a gate crossing: nothing ran short that the step knows of (the leave behavior's reason is a content formula). `Migrated`'s doc comment now says so and covers gate crossings; schema regenerated.
- `From` is the body's map when it crosses, not necessarily a town.
- No `TownEmptied` for a town the party is in when its last resident leaves: filed as question M3-11.F1.F1, the most reversible choice meanwhile.
- `residents_test.go`: `townField.wait` now returns the events it collected.
