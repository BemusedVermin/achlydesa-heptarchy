# M5-10.F1 · Save the pocket and the export count's source across a load

## Goal

A game saved after an export loads with the same ground: the pocket and the deep around it as they were.

## Context

- `internal/core/explore/export.go` keeps the pocket as chunk copies in memory only; `explore/generate.go` notes that a loaded game builds its source before the saved export count is restored.
- So after a load the map is the export-0 deep, with no pocket, and the party may stand in new ground.

## Deliverables

- Restore `ExportCount` before the source is built on load, and save the pocket (its chunks or its cells as edits) so the load rebuilds the same fixed layer.
- A save round-trip test after an export.

## Spec

Suggestion: save the pocket chunk keys; on load, rebuild the pocket from the export-(n-1) source plus saved edits is not possible once exports chain, so save the pocket's cells (a run-length list per chunk). Bump the save version.

## Acceptance criteria

- [x] Save after an export, load, and `Game.Hash` and the map match.
- [x] `go tool task check` passes.

## Out of scope

- Changing how exports are scheduled.

## Notes
