# M2-12.F1 · Hot reload does not refresh content cached at game start

## Goal

After `Game.SwapContent`, every package that copied something out of the content registry when the game started sees the new values, or the swap says which changes need a restart.

## Context

- `game.New` builds the clock from `Content.Calendar()` once, and packages may keep other values they read at install time. `SwapContent` only replaces `w.Content` and re-validates, so such caches go stale. Tile glyphs, templates, actions and text are read live and do update.

## Deliverables

- Audit `clock` and each installed package for values cached from content at install time.
- Make them re-read, or have `SwapContent` report that the change needs a restart.

## Spec

Suggestion: add an optional reload hook that packages register at install and `SwapContent` calls after validation.

## Acceptance criteria

- [x] Editing the calendar in `content/data` under `--dev` either takes effect or logs that a restart is needed.
- [x] `go tool task check` passes.

## Out of scope

- Reloading Go code.

## Notes

Filed by M2-12, then done in the same PR. The audit found two caches: the clock's calendar (now `Clock.Reset`) and the timeline's settings (now `timeline.Reload`); `Game.SwapContent` calls both after validation. Tested by `TestSwapContentRefreshesTheCalendarAndTimeline`.
