# M2-09.F1 · Give a crawling part the actions to fight with

## Goal

A severed part that crawls off (`spawn_from_part`) can start actions, so it really fights, not only stands on the map with a `hunt` controller.

## Context

- `internal/core/combat/effects.go`, `applySpawnFromPart`: the new body's identity template is the part's template (for example `part.remnant_arm`).
- `internal/core/actions/actions.go`, `known`: a body knows the actions of the content template its identity names. `part.remnant_arm` is no template, so the crawling body knows none and the hunt controller can only wait.
- M2-09 acceptance only needs the body, its position, allegiance and `hunt` Actor, so it passes; the crawling arm is still harmless.

## Deliverables

- A way for content to say what a crawling part acts as, for example an optional `crawls_as` template ID on a part template, used by `spawn_from_part` as the body's identity, or an `actions` list on the part template.
- A test that a crawling arm attacks an adjacent party member.

## Spec

Suggestion: add `crawls_as: "template.crawling.arm"` to `content.PartTemplate`, with that template giving the actions and appearance. `spawn_from_part` uses it when set and falls back to today's behavior. Needs a design check on what a crawling part can do (strike only, or more).

## Acceptance criteria

- [x] A crawling arm in the sample content starts a swing at a hostile in reach.
- [x] `go tool task check` passes.

## Out of scope

- Tuning how often parts crawl (M7).

## Notes

Also the alert text names such a body through `text.template.part.remnant_arm`, a stopgap added by M2-09; a `crawls_as` template would replace it.

Triaged 2026-11-23: todo in M2, because M2-11's crawling-part encounter needs a crawling part that can fight.

### Implementation (M2-09.F1)

- **What was built:** `content.PartTemplate.CrawlsAs` (`crawls_as`, a template ID). `spawn_from_part` uses it as the new body's identity, which gives the name, actions, tags and lists, and copies the template's appearance. A part without one falls back to today's behavior: identity is the part template, with no appearance. `part.remnant_arm` crawls as the new `template.crawling.remnant_arm`.
- **Loader check:** a `crawls_as` must name a template that exists and sets none of `body`, `party`, `actor`, `faction`, `protected`, `inventory` or `triggers`. `spawn_from_part` would silently ignore those fields, because the effect's parameters give the faction and controller.
- **Design taken meanwhile (rule 9):** the crawling arm knows only `action.strike`, loaded with `type.cut`, and has no `crawls` tag, so Stand doesn't freeze it. Its glyph is a magenta `a`. All of this is open in question M2-09.F1.F1.
- **Stopgap removed:** M2-09's `text.template.part.remnant_arm` is gone from `content/data/text.cue`. The name is now `text.template.crawling.remnant_arm`, in `templates.cue`.
- **Files outside the Deliverables:** `internal/content/load.go` (check), `internal/content/types_go_gen.cue` (regenerated), `internal/content/bodies_test.go`, `content/data/bodies.cue`, `content/data/text.cue`.
- **Tests:** `TestACrawlingArmSwingsAtAPartyMemberInReach` and `TestACrawlingPartTakesItsCrawlsAsIdentity` (with and without `crawls_as`) in `internal/core/combat/graft_test.go`.
- **Follow-up filed:** M2-09.F1.F1 (question: what a crawling part can do). It also notes that `part.remnant_core` has no `crawls_as`.
