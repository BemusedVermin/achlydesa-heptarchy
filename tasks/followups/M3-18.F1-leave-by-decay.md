# M3-18.F1 · Let leave pick the gate to the less-decayed neighbour

## Goal

A remnant leaving decayed ground crosses the gate to the neighbour with the least decay, not the nearest gate.

## Context

- `internal/core/agents/leave.go` `stepLeave` walks to the nearest gate of the map.
- `behavior.remnant.leave` in `content/data/behaviors.cue` can only say when to leave, not where. In the playground the den has one gate, so it works; a map with several gates may send a remnant to more decayed ground.

## Deliverables

- `internal/core/agents/leave.go`: an optional `leave` param, an Expr over the region record of each gate's neighbour, that ranks the gates (lowest wins, then nearest).
- `content/data/behaviors.cue`: the remnant's behavior uses it.
- Tests.

## Spec

Firm: content picks the ranking; Go only applies it. A suggestion for the param name: `prefer`.

## Acceptance criteria

- [x] A remnant in a map with two gates, one to more decayed ground, leaves by the other.
- [x] `go tool task check` passes.

## Out of scope

- Gate choice for other families.

## Notes

Filed by M3-18, then done in its pull request. Deviations from the sketch: the formula is a behavior field, `rank`, not a `leave` param, so any primitive that picks among options can use it. Highest rank wins, matching `consider`. Content ranks gates by the remnant's `need.undecayed` times how far a gate's ground falls below the decay it flees, so the need drives the choice. `RankEnv` and `Registry.BehaviorRank` are new in `internal/content`.
