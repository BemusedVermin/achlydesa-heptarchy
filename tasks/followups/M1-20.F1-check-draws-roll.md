# M1-20.F1 · Effect checks must not draw from the RNG

## Goal

Asking whether an action could start never changes the world's random state. Today it can, so a frontend that builds the view (or the timeline's usable hook) would play a different game from a replay that doesn't.

## Context

- `effects.params.env` draws one `roll` from the `effects` stream every time any Expr parameter is evaluated, including inside a primitive's `Check`.
- M1-20 calls `effects.Check` while listing options (`View`) and in the usable hook (every `decisionTick`). No primitive's `Check` reads an Expr parameter yet, so nothing diverges today. M2-04's primitives will.

## Deliverables

- A way to evaluate a `Check`'s parameters without consuming the stream, for example drawing the roll lazily only when the formula names `roll`, and giving `Check` a context whose roll is fixed at 0 (or refused).
- A test: build the view twice around a check that reads an Expr parameter, and show the `effects` stream state is unchanged.

## Spec

Suggestion: compile formulas with a flag saying whether they use `roll`, and only draw when they do. A `Check` that needs `roll` is a content bug and should be rejected at load.

## Acceptance criteria

- [ ] Building a view and running the usable hook leave `w.RNG` state unchanged for an action whose check reads an Expr parameter.
- [ ] A `Check` that uses `roll` fails `effects.Validate`.
- [ ] `go tool task check` passes.

## Out of scope

- New primitives (M2-04).
