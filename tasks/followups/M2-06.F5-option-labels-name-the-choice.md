# M2-06.F5 · Option labels show a chosen record's ID, not its name

## Goal

An option for a form loaded with a type reads "Strike: Cut, Salken", not "Strike: type.cut, Salken".

## Context

- Found while writing M2-06's tests: the labels in the view are `Strike: type.burn, Salken (lands in 3, busy 7)`. `internal/core/actions/options.go` (`label`) puts the choice's raw value into the text.
- Rule 4: player-facing strings are text IDs, rule 7: the view comes from the core. A record has a `name` text ID.

## Deliverables

- `label` renders a value that names a record by that record's `name` text.
- A test in `internal/core/actions`.

## Spec

Firm: use the record's `name` where the value names a record with one; keep the raw value otherwise (a direction has its own text).

## Acceptance criteria

- [ ] The label of a Strike with Cut names "Cut".
- [ ] `go tool task check` passes.

## Out of scope

- Redesigning options.

## Notes

Visible in any frontend that shows `Option.Label`.
