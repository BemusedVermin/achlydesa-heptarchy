# M2-06.F4 · List consumable types the pack lacks as disabled options

## Goal

A player who has run out of lake water still sees Strike with Soak, disabled with "The pack has no lake water", rather than the option vanishing.

## Context

- M2-06's `type` choice offers the innate types and the consumable types whose item is in the pack, as its spec says. A spent type disappears from the menu, and `actions.Validate` refuses it with the generic bad-choice reason.
- The `consume` effect's check already gives the right reason (`text.combat.pack_short`), and M2-06's acceptance reads "with no lake water, the option is disabled with a reason".

## Deliverables

- The `type` provider also offers consumable types the pack lacks (all of them, or the ones the party has carried).
- A test that such an option is disabled and carries `text.combat.pack_short`.

## Spec

The choice check in the `actions` package lets a provider offer a value and the form's effects refuse it. Decide how many types to list: all eleven would fill the menu.

## Acceptance criteria

- [x] With no lake water, the Soak options appear disabled with the pack-short reason.
- [x] `go tool task check` passes.

## Out of scope

- Menu layout (M2-10).

## Notes

Filed by M2-06. Started on the owner's say-so with M2-06 in the same PR.

Decision on how many to list: all consumable types, not only ones the party has carried, because the world does not record what a party has carried and the simplest reversible choice is every consumable. Menu layout and trimming it is M2-10's. The `type` provider no longer reads the pack at all; the form's `consume` check gives the disabled reason. Test: `TestTypesTheNeededItemIsMissingForAreListedDisabledWithTheReason`; `TestSoakStrikeSeversClayAndSpendsLakeWater` now expects the option listed but disabled.
