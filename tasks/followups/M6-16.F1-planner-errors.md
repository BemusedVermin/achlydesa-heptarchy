# M6-16.F1 · Let a planner report a content error

## Goal

`Planner.Plan` can return an error, so a content bug found while planning is reported instead of hidden.

## Context

- `internal/core/agents/mind.go`: `Planner.Plan(snapshot, goal) (Plan, bool)` has no error result.
- `internal/core/agents/htn.go`: a recipe whose `when` formula fails at run time, or that names a missing recipe, is skipped as though it did not apply. AGENTS.md says a run-time content bug returns an error and is never turned into a default.
- Load rejects a `when` that does not compile, so the case is rare (a formula that fails only on some beliefs).

## Deliverables

- `Planner.Plan` returns `(Plan, bool, error)`; `makePlan`, `decideFar`/`planAll` and every test planner follow, and the error leaves `Decide` as other content bugs do.
- `htnPlanner` returns the errors it now skips.

## Spec

- **Firm:** a failing recipe formula stops the game step with an error naming the recipe.

## Acceptance criteria

- [ ] A recipe whose `when` fails at run time makes the step return an error naming it.
- [ ] `go tool task check` passes.

## Out of scope

- GOAP (M6-15) should adopt the same signature when it lands; coordinate the order.
