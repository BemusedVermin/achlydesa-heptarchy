# M5-07.F1.F1 · Make verify fast enough to run on the large world at game start

## Goal

The real world uses `geography.deep`, with verify, and a game still starts quickly, so the large world has the connectivity guarantees.

## Context

- `internal/core/worldgen/verify.go`: verify now works from chunk summaries and holds at most `max_chunks` chunks. On the 400 by 400 by 64 world (seed 1) it takes about 58 s with `max_chunks: 256` and about 49 s with 1024, so `content/data/world.cue` still uses `geography.large`, which has no verify.
- Profile: about three quarters of the time is summarizing chunks. Filling the small pockets cascades: filling a pocket gives the open cells above it a floor, which makes new pockets for the next round. The first four rounds re-read nearly all 2,600 chunks, and each round reloads them through the earlier stages (cave noise), since a sweep larger than the budget gets no reuse.
- AGENTS.md rule 3 allows chunk summaries to be computed on other goroutines as pure computations and applied in chunk order.

## Deliverables

- `internal/core/worldgen/verify.go`: a faster summary pass. Options: summarize dirty chunks in parallel (each worker with its own bounded ground over `Context.Before` plus the edits so far), or cut the number of fill rounds.
- `content/data/world.cue`: `geography: "geography.deep"`; drop `geography.large` from `geography.cue` and `docs/content-guide.md`.

## Spec

Same repair for the same seed whatever the number of workers. Peak chunks held stay bounded by content (per worker, if parallel).

## Acceptance criteria

- [ ] `go tool task run -- play --seed 1` starts within a few seconds on the real world with verify.
- [ ] The verify property tests still pass.
- [ ] `go tool task check` passes.

## Out of scope

- Guarantees across an export: M5-10.
