# M5-07.F1.F1 · Make verify fast enough to run on the large world at game start

## Goal

The real world uses `geography.deep`, with verify, and a game still starts quickly, so the large world has the connectivity guarantees.

## Context

- `internal/core/worldgen/verify.go`: verify now works from chunk summaries and holds at most `max_chunks` chunks. On the 400 by 400 by 64 world (seed 1) it takes about 58 s with `max_chunks: 256` and about 49 s with 1024, so `content/data/world.cue` still uses `geography.large`, which has no verify.
- Profile: about three quarters of the time is summarizing chunks. Filling the small pockets cascades: filling a pocket gives the open cells above it a floor, which makes new pockets for the next round. The first four rounds re-read nearly all 2,600 chunks, and each round reloads them through the earlier stages (cave noise), since a sweep larger than the budget gets no reuse.
- AGENTS.md rule 3 allows chunk summaries to be computed on other goroutines as pure computations and applied in chunk order.

## Deliverables

- `internal/core/worldgen/verify.go`: a faster summary pass. Options: summarize dirty chunks in parallel (each worker with its own bounded ground over `Context.Before` plus the edits so far), or cut the number of fill rounds.
- `content/data/world.cue`: `geography: "geography.deep"`; drop `geography.large` from `geography.cue` and `docs/content-guide.md`.

## Spec

Same repair for the same seed whatever the number of workers. Peak chunks held stay bounded by content (per worker, if parallel).

## Acceptance criteria

- [x] `go tool task run -- play --seed 1` starts within a few seconds on the real world with verify.
- [x] The verify property tests still pass.
- [x] `go tool task check` passes.

## Out of scope

- Guarantees across an export: M5-10.

## Notes


Triaged 2026-11-26: todo in M5, because the real world needs verify for its connectivity guarantees.

- Result on the 400 by 400 by 64 world (seed 1, 4 cores): verify takes about 5.7 s, down from about 62 s on the same machine. That is the whole of world generation's wait at game start (verify runs on the first chunk built). "A few seconds" is met on 4 cores; fewer cores take longer. I did not time the full TUI start, only the first chunk through the stages.
- What changed:
  - Chunks are summarized on several goroutines (one block of the dirty chunks each, on its own reader with its own `max_chunks` budget) and applied in chunk order. The repair is the same whatever the worker count (`TestVerifyIsWorkerIndependent`).
  - The ground before verify is built once per chunk and kept packed (a palette and a `uint16` index per cell, about 8 KB a chunk), so a round that reads a chunk again no longer rebuilds it through the cave noise. This was the largest cost. Memory grows with the world (about 21 MB on the large world) and sits outside `max_chunks`, which still bounds the unpacked chunks each reader holds.
  - Readers take edits into the chunks they hold instead of through the map's edit overlay (a map lookup per read).
  - Chunk tables are kept for every chunk as `int16` (they were capped at `max_chunks` and rescanned on a miss).
  - Each crossing remembers the area it leads into, looked up again only when that chunk is scanned again, so a round no longer hashes every crossing.
  - `set` marks the dirty chunks from a key range rather than listing cells.
  - After a corridor is carved, further corridors in the same round are allowed as long as they read no chunk the earlier ones changed, so far fewer rounds are needed. Tried and dropped: skipping to a farther target on a conflict (slower: failed searches cost more than the rounds they saved).
- The carved corridors can differ from before for the same seed (corridor order within a round changed), as in M5-07.F1; the guarantees are the same and the property tests pass.
- `geography.large` is removed (content, `docs/content-guide.md`); `world.cue` uses `geography.deep`. `explore/populate_test.go` used `geography.large` as a test id and now uses `geography.deep`, still cut to its first stage.
- `export_test.go` gained `RegisterVerifyWorkers` so the test can fix the worker count.
